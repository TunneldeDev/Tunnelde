# 架构

[English](architecture.en-us.md)

后台工作使用共享任务服务、由生命周期管理的任务来源适配器，以及可选的任务可见性。参见[后台任务接入](development/background-tasks.zh-cn.md)。

## 分层

| 层       | 位置                                                                                                    | 职责                                                           |
| -------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 界面     | `src/features/*`                                                                                        | 按主机、终端、文件、编辑器、监控、插件和设置等功能划分         |
| 组件     | `src/components/{layout,ui}/*`                                                                          | 工作台布局，以及表单、浮层和展示基础组件                       |
| 状态     | `src/store/*`                                                                                           | 工作区、设置、主机、SSH、传输、编辑器等 Zustand 状态           |
| 公共库   | `src/lib/{api,files,text,prefs,session,plugins}/*`                                                      | IPC 封装及类型、文件操作、外观、终端输入和剪贴板               |
| 测试     | `tests/*`                                                                                               | 对应上述模块的测试，不与实现文件混放                           |
| 命令     | `src-tauri/src/commands.rs`                                                                             | 校验输入并调用相应模块的 Tauri 命令                            |
| 领域逻辑 | `src-tauri/src/ssh/{session,files,monitor}.rs`、`plugins/{mod,marketplace}.rs`、`vault.rs`、`update.rs` | SSH、文件传输、远端采样、插件宿主、凭据和更新                  |
| 存储     | `src-tauri/src/db/*`                                                                                    | 使用编号迁移的 SQLite 数据，包括主机、设置、信任记录和命令历史 |
| 平台     | `src-tauri/src/{lib,state,settings}.rs`、`platform/{window,tray,menu,logging,system}.rs`                | 应用组装、窗口、托盘、菜单、日志和本机采样                     |

## 启动与窗口显示

原生主窗口以隐藏状态创建。窗口状态恢复先应用保存的尺寸、位置和最大化状态，设置再应用原生窗口外观和背景色。窗口状态插件不恢复可见性或窗口装饰，这些由设置和启动、托盘处理逻辑负责。

前端先应用外观和语言，再公布设置就绪，随后恢复插件视图元数据和工作区布局。所选的内置字体加载后，工作台发送 `main_window_ready`；原生层收到后才恢复全屏并显示窗口。托盘、程序坞和再次启动共用这一就绪门槛。后台更新检查不阻塞显示，字体加载失败时使用后备字体；这里不等待动画帧，因为隐藏的 WebView 可能暂停回调。

启用 `releaseWebviewInTray` 后，隐藏主窗口会请求前端保存检查点。窗口仍处于隐藏状态时，原生层只接受当前请求令牌，将有限大小的快照保存在内存中，然后销毁 WebView。弹窗和视图持有的写入会推迟检查点；请求取消时会重新连接已分离的终端。分离期间，SSH 输出使用序列屏障和最大 4 MiB 的队列；达到上限时通过通道背压控制数据，而不是截断 ANSI 或 UTF-8。恢复使用 xterm 序列化器和固定版本的适配器，处理解析模式、保存的光标与不完整控制序列。

进程在没有窗口时仍保持运行，直到显式退出。托盘、程序坞或再次启动会重新创建窗口，在主线程恢复原生位置、尺寸及外观，并再次经过启动就绪门槛。WebView 创建避开同步事件回调，以免发生 WebView2 死锁；窗口几何恢复在主线程执行，以避免窗口状态缓存与尺寸事件之间的锁顺序冲突。恢复内存中的工作区和草稿后，启动逻辑会重新对齐原生会话、传输和插件事件。

## 数据

- 数据库：`<app data>/tunnelde.db`，使用 SQLite WAL。
- 插件：`<app data>/plugins/<id>/`。
- 日志：平台日志目录；设置覆盖位置时使用 `<data>/logs`。
- 密码：操作系统凭据存储，服务名为 `dev.tunnelde.app`，账户为主机 ID。

环境变量 `TUNNELDE_DATA_DIR` 可指定临时数据配置，`TUNNELDE_PLUGINS_DIR` 可指定独立插件根目录，`TUNNELDE_NODE` 可指定插件使用的 Node 可执行文件。只有用户同意使用系统运行时后才会读取 `TUNNELDE_NODE`，它不能绕过运行时授权。插件设置和对话位于各插件的独立存储中，插件密钥使用独立的系统密钥环身份；可移植设置配置不包含这些数据。

## 助手执行

独立插件市场提供助手集成和其他插件。受控聊天组件将模型配置与所选的本地或 SSH 执行目标分开。位置菜单使用活动 SSH 元数据；SFTP 用于解析主目录和工作目录，无需列出目录。重连后，保存的目标身份只会重新绑定到同一主机。

受支持的 CLI 和 API 集成通过有界的原生任务传输运行，可在本地或 SSH exec 通道执行。需要部署远端运行时或扩展时，会征求用户同意。桌面桥将工具调用限制在选定范围，限制回调和任务所有权，并通过 SSH 标准输入传递配置及选定凭据。普通运行使用活动连接；可选的原生监督程序提供独立的脱离连接、持久运行模式。

## 网络与资源生命周期

`network.rs` 按主机或插件覆盖、功能单独选择、全局默认值及系统路由解析网络配置。HTTP 客户端和 SSH TCP 使用同一套配置模型；代理密码以 `proxy:<id>` 保存在凭据库中。SSH 支持有界 HTTP CONNECT 和 SOCKS5 协商。跳板路径以 `route:<host-id>` 存储在 SQLite 中，每一跳都在认证前检查实际服务器密钥；嵌套 SSH 通道和跳板句柄由目标会话持有。

持久化桌面传输以 `transfer:<id>` 保存任务，使用 `transfer-file:<id>:…` 保存逐文件检查点，并用 `transfer-backup:<id>:…` 记录覆盖恢复信息。重连时通过稳定主机 ID 和端点地址重新绑定任务。正常关闭且未改变的检查点采用有限范围的首尾校验；崩溃、变化或旧格式检查点使用完整前缀校验。源文件时间戳和备份归属检查辅助续传与恢复，但不能保证文件操作对并发修改具有原子性。没有备份事务的新远端覆盖任务在上传前协商独立的 SFTP 提交通道，使用 OpenSSH 原子重命名扩展发布已关闭的暂存文件，不创建或删除备份；已有备份事务保留恢复记录。插件传输受插件运行时所有权约束，不自动获得跨重启的持久权限。

传输调度器在打开文件前原子预留源端和目标端的通道预算。全局最多运行四个任务，每个远端端点从其 SSH 连接的四个传输通道额度中预留两个。等待中的任务仍可暂停或取消，且不会提前打开传输通道。不同连接上的任务可以绕过受其他连接阻塞的任务继续执行。等待带宽额度时，显式偏移的 SFTP 管线仍会被轮询，请求数和缓冲区均受限。后台任务窗口在拖动期间预览位置和尺寸，不在每次指针移动时更新 React；松开后保存布局，并将布局纳入托盘检查点。

转发注册表管理监听器、活动套接字和远端转发路径；取消令牌覆盖建立过程和运行中的连接。断开、删除或撤销插件权限时，只取消相应资源。挂载注册表管理 SSHFS 子进程和直接 SFTP 标准输入输出桥，预留规范化挂载点，并在报告成功前检查系统中的挂载可见性。两个注册表都跟踪插件运行代次，旧运行时退出不会关闭新运行时的资源。忙碌挂载的清理保留可重试记录，同时立即切断已认证访问。

声明式插件使用有界 JSON 视图，不提供可执行命令，也不调用 Node。`mounts.*` 与 `forwards.*` 使用独立的读写权限；原生界面块和可执行宿主调用遵循相同的授权及资源所有权规则。

## 事件

`src/lib/events` 管理有类型的原生事件和本地域事件订阅。同名原生事件共用一个传输监听器；每个调用者持有独立、可重复调用的释放函数，也可提供 `AbortSignal`。注册过程中取消时，稍后完成的监听器也会被释放。监听器异常互相隔离，诊断信息仅包含名称和订阅者数量，不含载荷。事件总线不保留历史或应用状态；SSH 字节块按到达顺序传递，不做防抖、合并或重放。

启动模块管理自身的监听器、外观观察器、工作区订阅和持久化定时器。原生注册失败时，各订阅独立按有限退避策略重试；恢复时读取对应的设置、插件、安全、会话、更新或传输快照，由各状态存储拒绝过期快照。释放启动模块会取消待完成的设置、释放订阅并刷新计划中的工作区持久化。启用托盘 WebView 释放时，关闭到托盘也遵循这一生命周期，见[启动与窗口显示](#启动与窗口显示)。

插件工作区请求与市场监听器使用支持事务式注册的订阅组：部分注册失败会释放已成功及迟到的监听器，随后可以重新启动整个组。市场恢复时重新读取配置，以对齐注册失败期间错过的编辑。本地历史和文件失效通知使用类型化辅助函数，同时保留浏览器 `CustomEvent` 边界。历史视图先注册再首次读取，并用请求版本防止旧结果覆盖新结果。

| 事件                 | 载荷                             |
| -------------------- | -------------------------------- |
| `ssh://data`         | 会话终端字节                     |
| `ssh://closed`       | 会话 ID 和关闭原因               |
| `sftp://transfer`    | 传输进度、完成状态和错误         |
| `sftp://changed`     | 创建任务或延迟清理后对齐持久任务 |
| `plugin://state`     | 插件启动、停止或失败后的状态     |
| `plugin://event`     | 插件身份、运行代次及有界事件载荷 |
| `settings://changed` | 已提交的应用设置                 |

命令历史视图还订阅成功记录历史的通知，使已挂载的主机专属面板无需依赖导航即可更新。

## 发布流程

`dev` 是受保护的默认分支和贡献目标，`main` 保存稳定发布版本。贡献可通过 rebase 或 squash 合并到 `dev`；保留的每个提交标题都须符合 Conventional Commit。发布汇总将 rebase 后的提交关联到 PR，保留作者、共同作者和变更说明。向 `main` 推进版本使用 **Create a merge commit**。

每次更新 `dev` 都会维护一个生成的 `release/dev-to-main` PR，但不会启动安装包构建。PR 的内容来自 `dev`，并同步版本、汇总 CHANGELOG 和源码标记。准备提交同时以 `main` 和 `dev` 为父提交，最终推进时保留原始 `dev` SHA。历史 CHANGELOG 保持不变；更新生成引用前会重新核对实际引用。

Beta 和稳定版由不可变版本标签触发。手动运行 **Prepare Beta** 会为隔离的 `dev` 快照设置版本，并显式调用标签发布器，因为 `GITHUB_TOKEN` 创建标签不会触发 push 工作流。稳定版为审查后的 `main` 合并提交打标签，并使用同一发布器。Nightly 发布已停用；开发测试使用本地构建，不创建公开标签或 Release。

可复用 Release 工作流构建四个桌面目标，验证签名、所有安装包和 `latest.json` 后才公开草稿。Release 标题包含完整版本标签。构建期间即使 `dev` 继续前进，已打标签的源码仍有效，但仍会验证其祖先关系。历史 Release 和标签保留；Beta 不会成为最新稳定版。应用只提供正式版和 Beta 渠道，按 SemVer 选择而不依赖 Release 列表顺序。历史 Nightly 元数据仍可读取，但拒绝发布新的 Nightly；旧 Nightly 偏好迁移到正式版，更新边界拒绝不支持的渠道。辅助程序仅作为 Actions 构建产物，不进入桌面 Release 下载。

仓库令牌显式触发生成 PR 的 CI 并写入 PR 策略状态，不需要个人令牌或 App 凭据。具有较高权限的策略工作流仅执行受信任目标分支的代码。`main` 和 `dev` 受保护，不允许机器人绕过或直接提交发布内容。保护规则、源码核对和恢复操作见[发布运维说明](releases.zh-cn.md)。

两个 macOS 桌面架构均在 `macos-15-intel` 上构建：Rust 与已安装的 Apple SDK 交叉编译 `aarch64-apple-darwin`，x64 构建目标为 `x86_64-apple-darwin`。发布前对每个应用进行 ad-hoc 签名，并检查 Mach-O 架构和代码签名；更新器签名是另一套签名。这减少了对托管 Apple Silicon runner 容量的依赖，但不能替代在 Apple Silicon 上测试。原生辅助程序 CI 在 Intel macOS 上运行，也会编译并检查 arm64 二进制。

桌面库仅输出供应用可执行文件使用的 `rlib`，不构建未使用的 C 静态或动态库；完整 LTO 和体积优化仍保持启用。发布依赖缓存为每个目标使用稳定共享键，使 Build performance 工作流可从 `main` 恢复并刷新同一缓存，供后续标签发布使用。可复用发布工作流从 `main` 运行，避免缓存仅归属于单个标签。

可运行 Build performance，在相同源码、编译器、发布配置和 Intel runner 镜像下比较原来的三种库构建与 `rlib`。摘要报告耗时及原始、gzip 可执行文件大小，Actions 构建产物保留 Cargo 编译器时间图表。比较前应检查缓存恢复日志。发布构建也将编译器计时保留为 Actions 构建产物；测量结果和报告不加入公开 Release 资源。

需要用更新后的构建基础设施恢复中断草稿时，可从 `main` 触发 Release 并将 `existing_tag` 设为原版本标签。工作流构建原标签源码、复用草稿、替换桌面资源并重新生成经验证的更新清单；不会移动标签或增加版本，也拒绝覆盖已公开的 Release。除非选择 `build_helpers`，可选辅助程序构建产物仍保留在原工作流运行中。

CI 检查仓库卫生、Rust 格式/Clippy/测试、Web 版本和国际化/类型/代码检查/测试/构建，并在 Windows、macOS 和 Linux 上检查原生辅助程序。独立插件市场验证包清单、确定性归档和校验和、SDK 元数据及插件测试。
