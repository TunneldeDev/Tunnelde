# 原生文件保存的安装与恢复

[English](../../en-us/development/native-file-saves.md)

原生保存仍为实验实现。编辑器继续使用现有保存路径，安装及新原生保存流程尚未启用。
内部协议可用不表示它已成为稳定的本地或插件 API。

## 归属与存储

`ssh/files/native_save` 分开维护协议契约、传输、私有恢复日志、凭据存储和桌面恢复投影。
日志位于 `<数据库位置>/native-file-saves/recovery.sqlite3`，独立于可以重置的应用数据库。
操作控制令牌保存在独立的系统凭据服务中，不进入日志、安装记录或前端消息。

安装意图记录保存实际认证目标、账户与作用域、明确的辅助程序和状态目录、安装包版本／
平台／哈希，以及原始所有者代次，不保存密码或文件内容。记录校验和用于发现损坏，
不能防止另一个有权重写私有数据库的进程伪造记录。

## 安装边界

明确授权的安装必须先记录意图，才能修改远端。状态如下：

| 状态       | 含义                           | 恢复行为                                   |
| ---------- | ------------------------------ | ------------------------------------------ |
| Reserved   | 尚未授权任何远端修改           | 可以丢弃准确匹配且确定未发送的预留         |
| Dispatched | 原始工作者可能已经修改远端     | 保留原始路径供检查，不重复安装或删除残留   |
| Ready      | 原始工作者收到匹配的初始化权威 | 保留原始辅助程序选择和权威，供后续保存使用 |

只有原始检查点成功才会产生一次性安装许可，重启或读取状态不能重建该许可。
迟到回复必须匹配原始修订号、所有者和计划；账户、作用域或系统不符时，不得替换原始权威。
回复丢失或路径不存在，都不能被当成远端清理成功的依据。

安装和状态路径参与现有文件准入事务：旧操作不能删除或覆盖这些路径的祖先与后代，
原生保存也不能写入这些位置；不会因此将整个文档作用域变为只读。
主机别名、Windows 的 SFTP 与原生路径写法采用保守比较，同时检查 SFTP 规范路径。

## 格式与限制

打开日志不会创建或升级它。明确执行安装格式升级时，保留日志身份、旧原生操作和旧准入
记录，增加版本 3 的安装表。读取仍支持版本 1 和 2。旧宿主拒绝版本 3，以免忽略安装预留；
直接调低数据库版本号不是受支持的迁移方法。

最多保留 32 条安装记录，每条最多 64 KiB；容量不足时不会淘汰未知安装。
数据库损坏、结构不完整或权威被替换后保持不可用，读取不会重置证据。
事务沿用恢复日志的同步检查点。进程退出测试覆盖已提交状态和未提交结构升级的回滚，
不等于验证了所有存储设备的断电行为。

未发送或结果未知的安装会显示在现有恢复列表，包含可检查的路径与目标，但不暴露所有者
代次、安装包哈希、日志身份或私有控制字段。历史记录不会被显示为安装程序当前仍在运行。
