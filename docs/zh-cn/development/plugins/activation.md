# 插件依赖与激活

[English](../../../en-us/development/plugins/activation.md)

必需运行依赖目前属于实验能力，表示声明插件启动前必须就绪的已安装插件。
它不等于 JavaScript 模块导入，不允许读取其他插件的存储，也不共享权限。

```json
{
  "apiVersion": 2,
  "dependencies": [{ "id": "shared-tools", "version": "^1.0" }]
}
```

这是清单片段，仍需正常声明插件身份、运行环境、入口与权限。版本范围使用 Rust
`semver::VersionReq` 语法，例如 `^1.0`、`>=1.0, <2.0`，不支持 npm 的联合范围或连字符范围。
预发布依赖需要匹配的显式预发布比较条件，稳定范围不会自动接受预发布版本。
纯主题包不能声明必需运行依赖。

必须使用清单准入版本 2，避免旧版宿主忽略未知的依赖字段后直接启动插件。
只支持 v1 的旧宿主会拒绝 v2 包；已有 v1 插件继续兼容。
JSON-RPC API 及其稳定契约仍为版本 1。`initialize.apiVersion` 是插件清单版本，
`initialize.hostApiVersion` 为 1。这次调整不代表全部 API 已稳定，也不代表应用已满足 1.0 发布条件。

## 审阅与执行

宿主从已安装元数据生成计划，此过程不启动引擎、不探测 Node、不弹授权框，也不下载插件。
缺少依赖、版本不兼容或存在循环时，会停止并报告具体原因。插件详情展示依赖 ID 和版本范围，
安装仍须用户明确发起。

启动时逐个审阅插件并申请各自权限，随后将完整审阅清单的包指纹和原授权代次绑定到启动凭据。
等待期间发生替包、撤销或重新批准，会使捕获的请求失效，旧请求不能借用新批准。
内部预览与启动凭据只是当前宿主进程内的 WebView 实现，不是插件 SDK 命令。

所有插件的批准字节、宿主及 UI SDK 兼容性、运行环境预检全部通过后，才启动第一个引擎。
WASM 在此阶段准备；Node 每个计划仅解析一次，再分别检查每个插件的版本要求。
宿主不会默认选择用户安装的 Node，运行环境选择与使用系统 Node 的授权仍需明确完成。
预检失败保留已有批准，不启动任何插件。

依赖先于使用方启动。原生初始化与可信前端激活都完成后，依赖才算就绪。
同一运行实例的启动请求共享执行，但保留独立等待者。取消一个根插件只结束它对依赖的等待，
不影响其他等待者；最后一个未完成等待者退出时触发清理结算。
根插件后续失败或取消时，已经就绪的依赖继续运行。
停止或撤销依赖会通过已有运行归属与清理服务，退役正在使用它的插件。
请求取消不代表远端资源已经实际停止。

## 边界与发现

通过 `extensions.describe().runtime.activation` 检查支持情况，缺失时应视为不支持。
当前每个插件最多 16 个依赖，一组最多 64 个包、256 条边、32 层深度，每个范围最多 160 个 UTF-8 字节，
计划读取最多 4,096 条已安装目录记录。最多并发 16 个图启动请求，整组预检限时 60 秒。
阻塞文件读取与 WASM 准备共享 16 个工作名额，即使等待方取消，也要等实际工作结束才释放名额。
共享引擎启动还保留各自的协调器数量限制和就绪时限。

宿主的声明契约、图解析、准入、预检、执行、协调分别归于
`src-tauri/src/plugins/runtime/activation/` 下的独立模块。
插件仓库 SDK 的依赖声明与发现类型归于 `sdk/rpc/runtime/activation/`。
市场发布校验声明结构与大小，范围语法和匹配由宿主的 Rust SemVer 解析器最终判定。
SDK 同步会对照宿主实现校验发现目录中的限制。
