# 文件读取与预览生命周期

编辑器、内置预览及插件提供者预览共同使用 `src/lib/files/resources/` 下的宿主读取
生命周期。`target.ts` 固定不可变的请求坐标，`read.ts` 适配文本读取，`preview.ts`
管理原生预览凭据和有界文本组装。它们复用扩展运行层已有的 `ResourceScope`，
不另建取消引擎，也不增加公开插件方法。

目标保留原始路径，以及本地来源或明确的 SSH 会话 ID。它不是规范文件身份、
别名解析器、授权、快照或删除文件的依据。调用者之后修改来源对象不会改变
已经请求的读取目标。

销毁会停止投递并请求取消。原生 IPC 可能仍在进行，其作用域额度直到实际 Promise
结算才释放。消费者还根据当前文档或预览激活状态检查返回结果。关闭视图不表示
文件写入已停止或回滚。

## 预览所有权

每次提供者预览都使用宿主新生成的唯一凭据 ID。原生提供者发现尚未结束时关闭
视图，会先请求关闭；打开成功结果迟到后再次关闭，因为原生注册可能晚于第一次
关闭请求。清理始终使用请求 ID，不使用尚未验证的返回 ID。正常打开的凭据保留
到视图关闭或渲染器失败。

读取前校验返回 ID、选定渲染器、安全整数大小及原生渲染器限制：文本/Markdown
2 MiB、图片 32 MiB、PDF 128 MiB、音频/视频 1 TiB。文本每段最多读取 1 MiB，
在一个有界缓冲区中组装并校验 UTF-8 和 NUL 字节。打开、元数据、分段读取、解码、
PDF 或媒体失败时立即开始清理。重试使用新凭据；切换语言不重新打开正常预览。

保留文件句柄不承诺文件系统快照不可变。原生预览注册表、I/O 限制和远端会话检查
仍为最终依据；发出清理请求不能证明原生清理已经成功。

## 原生本地读取

本地预览区间、内置文本预览和插件本地文本读取复用
`src-tauri/src/services/files/read/`。服务解析用户明确选择的路径别名，再通过平台
标志打开普通文件，拒绝最终路径被替换为符号链接、重解析点或特殊文件。保留已打开
句柄，并串行执行定位与读取。Windows 读取允许已有日志写入者继续写入；编辑器用于
安全发布的严格句柄仍独立保留。祖先目录解析遵循操作系统，并非文件系统沙箱。

本地阻塞 I/O 与远端协议 I/O 共用最多八个排队或执行中的读取/打开任务。即使异步调用者超时或关闭，
容量仍由实际工作线程持有，直到它退出。已取消的排队工作跳过 I/O；等待文件游标锁的
读取在取得锁后再次检查取消。已经执行中的文件系统 I/O 仍可能继续完成。容量满时
返回明确的繁忙错误，不继续排队。单次字节读取最多 32 MiB，以保留整张图片预览；
HTTP 区间仍最多 1 MiB。文本前缀沿用调用方原有限制，多读一个字节判断是否超限。
其他程序仍可修改文件，保留句柄不等于获得不可变快照。

原生服务本身不授予插件权限。下述独立的公共内容资源边界负责权限、生命周期和
受限传输契约。

远端预览也复用同一来源服务，为每个来源保留独立的只读 SFTP 通道和已打开句柄。
每条 READ 都携带明确偏移和受限长度，不共享可变预读游标。收到短包时从实际返回的
位置继续补读，不越过请求区间。服务遵循协商后的包/读取限制，拒绝空 DATA 或超长
响应，并检查已打开句柄的普通文件类型及明确返回的大小。

调用者取消后，实际任务仍持有配额，直到当前协议响应结束，之后跳过后续请求并停止
投递。OPEN 确认迟到时关闭已放弃的通道。读取错误或整次读取超时会在释放配额前
关闭该专用通道，保留用户的父级 SSH 连接。来源通道最多 64 个，包含尚未完成的打开
和仍由任务持有的通道。打开最多 15 秒、单条协议响应最多 15 秒、整次读取最多 30 秒。

SFTP v3 不提供本地 `O_NOFOLLOW` 的保证，也不能控制服务器阻塞中的文件系统操作。
关闭通道表示请求释放远端资源，并不证明服务器的系统 I/O 已停止。来源固定的是句柄，
不是不可变文件内容；本层不能独立于公共资源边界授予权限。

## 编辑器请求

打开、关闭、断线或被新请求替代都会使旧读取失去投递资格。并发重连采用最后一次
明确意图。首次加载被打断时记录尚未读到基线，重连后可填入文档，避免误报冲突或
一直加载。断线期间输入的文本保留；已成功加载的草稿遇到远端基线变化时，仍需
明确审查。旧内存检查点通过已有加载/错误字段推断基线是否可用。

保存合并绑定文档代次和准确 Promise。被替换文档的旧写入不能阻塞新保存、清除新
任务、修改新基线或弹出过时错误。保存期间继续输入仍保留未保存状态。替换文档
不会取消、重放或回滚已经开始的写入；原生基线检查仍然必要，本层不是写入事务。

本地编辑保存与保留暂存的清理共用四个实际工作任务配额，与八个读取配额独立。
进入阻塞线程池前即占用配额；超额调用在文件 I/O 前返回 `editor.saveBusy`，调用方
保留草稿，等待当前操作结束后可重试。取消调用不会提前释放已排队或正在运行的
任务配额。线程池中尚未开始的取消任务跳过 I/O；已开始的保存会在路径锁等待后及
发布前检查取消。已获准执行的清理会完成安全事务，即使调用方取消等待。
已发布的保存仍发送提交通知，取消无法回滚。工作任务意外停止返回
`editor.saveWorkerFailed`，软件日志记录所属领域与阶段；本配额不能强行停止系统
I/O，也不代表远端写入副作用已经结算。

远端编辑保存和保留暂存的清理另有四个工作任务配额，打开 SFTP 通道前即占用。
超额调用返回 `editor.remoteSaveBusy` 并保留草稿；任务意外停止返回
`editor.remoteSaveWorkerFailed`。调用方停止等待后，独立工作任务仍持有路径锁和清理
预留。保存会在路径锁等待后及暂存、发布前检查取消；已确认的所属标记允许任务在
调用方退出后继续安全清理暂存。

发布准入与取消只有一个原子胜出方。准入后，任务等待 rename 回包及安全清理完成，
不会因为取消结果投递而重试或回滚该次 rename。已确认的保存由工作任务发送一次
文件变化通知，IPC 路由不再重复发送。无内容变化的保存仍协调观察方，且无需服务器
支持替换扩展。清理调用被取消后，已获准执行的清理任务同样会运行至事务结算。

这些配额约束的是客户端工作任务生命周期。SFTP 超时或丢失回包不能证明服务器端
操作已经停止。崩溃/丢失确认的持久结算、发布时插件权限与工具审批围栏仍属独立
待办；本次不新增公共写入事务 API，也不提供远端比较交换保证。

稳定编辑器 API 和实验性缓冲区比较交换契约不变。文件修改所有权、持久写入结算、
跨来源移动，以及完整的共享文件数据/订阅契约仍是独立待办。

## 公共只读内容资源（实验性）

普通前端和 stdio 插件可通过 `files.content` 读取字节，不需要宿主预览票据，也不会隐式选择
SSH 目标。`prepare` 明确传入 `{source:{kind:"local"},path}` 或
`{source:{kind:"remote",sessionId},path}`，只检查对应的 `fs.read` 或 `sftp.read` 权限。
路径必须为绝对路径。预留阶段只保留 20 秒的空描述符，不执行文件 I/O；`open` 仅能认领
已返回的 `contentId` 一次。SDK 在 I/O 开始前就知道 ID，即使打开响应丢失也可关闭。
关闭先于打开到达时会移除前置预留，迟到成功不能重新安装资源。未知预留响应不持有
文件或通道，并自动过期。

`read` 的偏移为 JavaScript 安全整数，长度为 1 到 49152 字节，末尾按打开时大小截断。
返回标准 base64、解码字节数与 EOF；SDK 校验后返回 `Uint8Array`。打开时大小必须能用
JavaScript 安全整数表示。句柄保留文件身份，不保证内容快照；文件被截断或修改时，
后续读取可能变化或失败。

通过 `sdk/files/content/client.mjs` 的 `createFileContentClient` 创建客户端；`open` 必须
传入所属方的 `AbortSignal`。所属方取消或调用返回句柄的 `close()` 均会退役资源。
每个客户端及宿主插件运行实例最多八个句柄，宿主总计 64 个，共用原生八任务 I/O 配额。
读取续期 60 秒空闲租约；`observe` 和 `subscribe` 仅观察句柄生命周期，不续期，也不监听
文件系统变化。超时后立即拒绝操作，单个宿主清扫任务在随后一秒内回收空闲句柄。
关闭可重复调用；取消后实际 I/O 配额仍由真实任务持有至结束。

预留与已打开来源均接入 `resources.snapshot`、
`resources.identify({kind:"fileContent",id:contentId})` 和 `resources.release`。
ID 不代替运行实例所有权；每次操作独立检查，插件停止、撤权和受限模式均会退役句柄。
释放已打开资源可能返回 `cancellationRequested`，因为关闭专用 SFTP 通道或本地句柄，
不证明已在运行的系统 I/O 被强制停止。父级 SSH 连接保持连接。受限 AI 工具的白名单
暂不扩展，须另行完成句柄与路径作用域契约。公共预览生命周期与表现另有
[实验性契约](plugins/file-preview.md)，文件修改事务仍独立推进；本批次不扩大稳定
API 集合。
