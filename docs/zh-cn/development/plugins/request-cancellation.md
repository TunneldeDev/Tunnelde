# 取消插件调用

取消属于实验性的传输能力。它沿用现有 API 版本和方法权限，不扩大稳定接口范围。

stdio SDK 的调用被取消或到达本地超时后，会发送 JSON-RPC `$/cancelRequest`
通知，通过 `params.id` 指定请求。显式关闭 SDK 时，如果管道仍可用，也会通知宿主
取消尚未完成的调用。标识符只属于当前连接中插件向宿主发起的调用。
通知没有顶层 `id`，自身没有响应。新宿主停止等待该请求，以原请求标识符返回
`plugin.api.cancelled`（`-32800`）。未知或已结束的标识符不产生影响。
旧宿主忽略通知，因此旧宿主上只会取消本地 Promise。

可信前端插件可以传入取消信号和超时时间：

```ts
const owner = new AbortController();
const answer = context.api.call<boolean>(
  "ui.confirm", { message: "是否继续？" },
  { signal: owner.signal, timeoutMs: 60_000 },
);
owner.abort();
```

前端传输先预留绑定令牌的请求票据，再发起调用。取消早于调用到达时，票据会失效，
避免取消丢失。前端令牌被替换或关闭，也会取消它所属的请求。本地取消后才到达的
预留响应会被释放，不再执行操作。已经取消的调用不分配票据。
票据标识符属于内部传输，不能控制其他所有者的请求。

每个传输登记表最多容纳 64 张待处理票据，每个所有者最多 32 张。
票据从预留开始经过 120 秒失效；前端调用默认本地超时为 60 秒。
接纳新请求前会清理超时的未使用票据。stdio 取消通知不占普通请求配额。

取消会终止异步等待，并关闭该请求尚未完成的原生确认框，但**不代表回滚**。
已经完成的写入、外部命令或已经开始的阻塞任务仍可能产生影响。
调用取消不能证明修改是否提交；丢失响应后不要自动重试修改操作。
应读取该操作的修订号或持久状态，遵循所属领域的恢复契约。
修改接口仍需单独实现提交围栏、资源限额、幂等和补偿，传输层不能替代这些机制。
