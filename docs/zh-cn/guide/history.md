# 命令历史

命令历史按已保存的主机保存在本地，每台主机最多 500 条；重复命令移动到顶部。
默认读取 200 条，请求数量限制在 1–500。空命令或超过 4000 个 UTF-8 字节的命令会被忽略。
现有历史 RPC 仍为实验性接口，本次共享服务改造不承诺完整 Shell 历史、修订分页快照或无损终端录制。

终端自动记录需要用户开启“记录终端历史”。它尝试解释终端输入，不属于 Shell 集成。
原始输入可能包含密码等敏感内容，不适合记录时应保持关闭。自动记录会跳过以空格开头的输入。
经用户明确授权 `history.write` 的插件可以通过 API 写入历史，这与终端自动记录是两项独立能力。
不要将秘密写入历史。

原生界面和插件 RPC 共用 `services::history`。服务返回独立的传输数据结构
`{ id, hostId, command, executedAt }`，保留原有字段名；`executedAt` 为 Unix 纪元以来的毫秒数。
`history.list` 需要 `history.read`，`history.record`、`history.delete`、`history.clear`
需要 `history.write`。授权仍由调用入口检查，记录命令要求主机已保存。
删除和清空保持幂等，插件 RPC 成功返回 `null`。

原生或插件修改成功提交后，统一发送 `plugin://domain-changed`：
`{ domain: "history", hostId, sessionId: null }`。写入失败、忽略的记录、删除不存在的条目或
清空空历史都不发送通知。删除操作在同一个事务中确认条目所属主机并删除，不在失效通知中携带命令内容。
工作台桥接只刷新对应主机的历史面板；旧版不带 `hostId` 的事件仍会刷新全部历史面板。
浏览器集成保留原有的本地 `tunnelde:history-changed` 事件，原生界面不会再为同一次操作重复发送本地事件。

面板读取全部保留记录（最多 500 条），将并发失效通知合并为一次后续读取，并忽略旧主机或
旧生命周期晚到的结果。事件只是重新读取的提示，不保证持久交付；新面板始终读取当前数据。
[实验性历史提供者](../development/plugins/history.md) 提供绑定修订的有界分页和可复用的原生列表。
旧 RPC 仍返回不分页数组，其余领域契约仍在开发中。
