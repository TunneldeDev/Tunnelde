# 面向 1.0 的核心契约收口

桌面应用拥有业务服务。Tauri 命令、本地自动化和插件 RPC 是这些服务的适配层，
各自的协议与权限独立。内部命令可调用，不等于它自动成为公共 API；应用版本更新
也不会自动将实验方法提升为稳定接口。

## 凭据归属

主机、代理和插件密钥使用通过 `AppState` 注入的应用凭据服务，系统凭据库的
service 为配置的应用标识。正式应用保留 `dev.tunnelde.app`；已有主机／代理密码
通过明确的旧键绑定继续读取，直到被修改或遗忘。新保存使用随机、不可复用的
系统条目名，确认写入后发布数据库绑定。隔离应用使用自己的 service，
不回退读取正式应用凭据。只修改数据目录不能隔离系统凭据；QA 构建还必须
使用独立应用标识。相同标识的实例有意共享该凭据服务。这是名称隔离，
不是阻止同一用户的其他程序访问凭据的操作系统安全边界。

原生保存恢复令牌继续使用独立的、由应用标识派生的 service。公共适配层
不能选择凭据 service 或修改应用标识，接口发现、日志和快照均不包含凭据值。

桌面私有 `host_editor_save`、`proxy_profile_save`、`credential_status` 以及
已审阅连接的凭据操作，通过有界阻塞工作线程完成系统访问和旧条目清理。
共用最多 16 个操作的容量，排队中的工作也占用容量，超限返回
`credentials.busy`。命令 Future 在工作线程准入前被取消时，排队操作不再开始；
准入后由线程持有容量直到系统访问结算，丢失回复不代表写入回滚。
原主机／代理、路由、信任权威、绑定修订和原始系统错误仍属于同一操作。
主机字段与路由原子提交，代理字段与绑定权威一起提交；后续凭据操作失败时，
编辑器仍收到已提交字段，保留编辑内容并对同一主机／代理重试。
状态查询读取当前绑定的凭据，可能需要系统授权；这些桌面命令不增加稳定 API。

第 6 次 Schema 迁移只存储元数据，不存储密码。短数据库事务负责条目意图、
CAS 发布、配置代次和精确条目清理；系统访问期间不持数据库、设置或路由权威锁。
陈旧写入不能发布自己的条目，也不能删除替代条目的密码。遗忘先发布墓碑，
再异步删除，不能回退旧键。主机／代理目标改变后不隐式沿用旧密码，显示修改则保留。
相关路由、代理选择和信任 A→B→A 会撤销旧权威；无关选择及显示修改不撤销。
密码发布只改变绑定修订，不使自身 SSH 确认失效。

独占存储后，启动阶段先分页恢复元数据，再启动 worker。系统写入失败保留原
unknown 意图；清理只针对原退役条目，不重放保存，失败 claim 留待重启恢复。
所有原生读取使用绑定，插件密钥仍遵守原命名空间与授权。这不是与外部系统修改
之间的原子事务；复制数据库且共用同一系统 service 不能得到独立凭据命名空间。
旧构建必须拒绝未来 Schema，不能静默降级。

Windows 与 macOS CI 使用随机 QA service，在真实系统凭据库上显式运行绑定生命周期
测试。夹具默认忽略，覆盖 Schema 5 迁移、替换、跨进程读取、持久遗忘、未发布条目恢复
和精确清理，并确认相邻 service 未被删除。子进程限时 60 秒，CI 步骤限时 3 分钟。
此托管环境测试不能证明已安装应用的 Keychain 授权、真实用户弹窗或原始桌面卡死原因。

已审阅 SSH 的保存密码回退读取也共享此工作线程容量。在实际 worker 准入、读取后和
认证使用结果前，分别校验原路由快照与凭据主机 scope；系统访问期间不持数据库锁。
审阅配置改变则丢弃读取结果，不刷新用户原审阅，也不向改变后的配置执行认证。
此边界与受审写入／删除共用不可复用条目绑定；修改在系统写入及发布前分别
校验原配置权威。

桌面 SSH 审阅准备同样使用此有界 worker 容量，因为捕获传输配置可能读取已保存的
认证代理密码。worker 实际运行时在访问代理凭据前核对显示主机与当前存储；排队不会刷新陈旧弹窗。
共享路由捕获在检查传输配置前核对已保存的连接字段和动态来源范围，并保留读取后的完整复核。
访问系统凭据前会释放数据库锁；读取期间发生变更时，仍可能需要丢弃已经完成的读取结果。
其他审阅操作保留各自的权威及调度规则。

更新、发布历史、插件市场及 helper 下载的 HTTP 代理凭据读取与客户端构建同样使用
有界凭据 worker。一次检查捕获一次网络设置，发现、退避标识、清单和保留的安装更新器
共用同一份已解析代理；结果发布仍受原有来源／渠道代次校验控制。市场下载在准备阶段
取消后不会迟到发出 GET；已准入的系统读取仍可能持有容量直到结算。历史查询的时限
包含路由准备，历史不可用时保留已选版本的说明。不放宽 TLS、签名或显式代理的回退
规则。系统代理客户端最多复用 30 秒，退避标识与该客户端保持一致。
不承诺对外部系统代理／密钥变更的系统级原子观察；其他凭据使用方
继续遵守各自边界。

原生代理诊断在共享有界 worker 中解析所选 TCP 路由后才连接。15 秒 TCP 预算
包含路由准备；准备超时或被放弃后，即使系统读取迟到返回，也不会再发起连接。
三个质量样本复用同一份已解析路由。可选 HTTPS 检查单独有 15 秒预算，包含
worker 上的客户端构建，保留 TLS 验证与所选代理。保存连接路由只校验代理选择
及 URL 字段，不读取保存的密码；受审凭据修改仍保留独立权威规则。

恢复浏览器的 probe、trust、connect 及最终 open 在持有注册表、连接和恢复元数据
权威 guard 之前完成慢速系统代理观察；观察对象不透明，不能通过 IPC 传入。
最终副作用匹配同一个 pending 对象和原恢复 token，再核对持久化主机、路由、
信任记录及 SSH 有效代理配置。数据库提交后的设置行即为权威，即使内存尚未
发布；存储损坏时拒绝准入，不静默使用默认值。无关代理和显示名称不撤销操作。
信任推进只更新获批端点及其别名，不在 guard 内再次读取系统凭据。

open 在异步准备期间预留已有连接；竞争请求返回 busy，不取消原持有者。取消、
失败或被放弃的接收只清理匹配的 pending，并关闭新获取的私有连接；复用的
用户连接保持独立归属。不承诺对外部代理或密钥变更的系统级事务：先观察传输，
再做最终纯配置校验。受审凭据写入／删除仍有独立修改权威与条目 CAS；
浏览器观察本身不构成凭据写入授权。

插件引擎及本地进程任务的代理环境在同一个有界凭据 worker 上准备，不占用
运行时线程。初始及最终数据库准入在互斥锁竞争时异步等待，并计入同一个
准备期限，避免阻塞在持锁凭据写入之后。入队前捕获持久化设置中的插件／进程
有效代理选择，应用原生环境前再次校验；直连和继承系统环境保持原有含义。本地任务的超时包含准备阶段，
期间取消、撤权或过期不会在迟到后获准启动。准备后在启动子进程前立即核对
原运行代次的授权和取消状态，中间不 await。这是启动准入，不是与外部凭据
变化或准入后并发撤权的系统级事务；已启动子进程沿用原有归属和清理规则。

## 兼容规则

- 稳定接口必须有明确归属的请求、结果和错误 Schema，说明副作用及生命周期，
  提供兼容样本和真实生产者／消费者测试。
- 同一契约主版本内，不得增加必填输入、收窄已接受输入、删除或改变已有输出含义，
  不得改变错误码含义。增加输出字段前必须确认消费者允许扩展字段。
- 修订号是不透明的持久代次标识。写入携带原修订号，陈旧编辑应失败，不能覆盖
  新设置。重试不代表重新授权，取消也不代表回滚。
- 事件默认用于失效通知，只有契约明确说明时才承诺可靠送达。消费者必须能从
  快照重建状态。重连和窗口重建不会恢复旧插件或旧运行代次的授权。
- 错误暴露稳定代码和安全的公共详情，解释性文字可以改进。日志应标明领域和阶段，
  不得泄露凭据。
- 弃用必须可发现并有文档，在新契约主版本移除前提供替代接口及迁移期。已有
  插件 v1 的稳定承诺继续有效，CLI v1 不替代它。

## 领域归属及发布门槛

稳定的本地协议 v1 仅涵盖以下七个方法。带版本的声明和不可变历史基线见
[兼容规则](local-api-compatibility.md)：

| 接口                                                               | 契约边界                                                                                                          |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `api.describe`、`app.info`                                         | 协议／方法发现与运行版本；离线 CLI 描述自身构建，不能替代宿主发现                                                 |
| `hosts.list`                                                       | 通过共享主机服务获取一次已保存主机快照；不含凭据、修改和插件主机源，数组顺序无保证                                |
| `sessions.list`                                                    | 一次运行连接快照；ID 标识连接而非永久主机，返回后也可能立即断线；`connectedAt` 是 Unix 毫秒时间戳，数组顺序无保证 |
| `preferences.schema`、`preferences.snapshot`、`preferences.update` | 仅公共设置；不透明修订、严格局部更新、集合整体替换和陈旧写入拒绝；不含迁移与凭据                                  |

快照不预留资源、不承诺事件送达；本地协议仅请求／响应，不提供事件流。设置提交
仍在应用内部发布普通失效通知。写入回复丢失时结果未知，应重读快照确认，不能自动
获取新修订后重放。调用者已是同一操作系统用户，凭据仅授予上述有限能力，不复用
插件权限，也不弹交互审批。

已有 16 个稳定插件方法保留独立冻结契约。更多本地修改、插件 UI、runner 和高级
传输恢复可在桌面 1.0 后继续保持实验状态，不作为首批稳定契约的前提。持续发布
门槛是历史客户端兼容、支持平台二进制检查、基本文件安全，以及实际安装／升级
数据保留验收；新增 API 方法不属于门槛。

以下是收口检查清单，不代表所有领域已经稳定。[本地 API](local-api.md) 是
第一批面向外部程序的适配入口。

| 领域           | 现有归属                                         | 承诺公共稳定前需要收口                                                         |
| -------------- | ------------------------------------------------ | ------------------------------------------------------------------------------ |
| 发现与错误     | `automation/contract.rs`、插件目录与历史核心样本 | 版本协商、认证、有界通信、结果与错误严格互斥、历史消费者                       |
| 主机           | `services/hosts.rs`                              | 独立公共 DTO；各适配层保留校验、审计、重命名与变更通知                         |
| 连接           | `ssh/session.rs`                                 | 连接和主机身份、信任认证、断线与取消语义明确，结果不携带凭据                   |
| 设置           | `services/settings/preferences/`                 | 冻结公共 Schema、修订冲突、校验与副作用顺序、重启要求，排除内部 Settings       |
| Profile 与存储 | `settings_profiles/`、`storage/`                 | 导入导出限制、迁移恢复和数据保留；不完整恢复保留实验状态                       |
| 转发           | `services/forwarding/`                           | 区分规则持久修订与运行连接身份、正确反映断线状态、复用校验                     |
| 文件与任务     | `services/files/`、`ssh/files/`                  | 基本复制、移动、取消、重连，安全保留源文件与清理；不能按路径缺失推断未知副作用 |
| 诊断           | `logs/`、`platform/logging/`                     | 有界分页、领域归属、游标筛选与脱敏规则；诊断不自动承诺可靠审计                 |
| UI 与扩展      | `src/lib/extensions/`、领域桥接                  | 保留已有稳定承诺；高级扩展与远端 runner 可以在 1.0 保持实验状态                |

不能用增加 RPC 数量替代这些边界收口，也不应把每个插件或高级传输恢复机制全部
做完作为首个稳定桌面版本的前提。即使延后高级功能，基本文件安全、实际安装和
升级数据保留仍需验证。

原生本地目录列表、新建目录、新建文件和删除使用 `services/files/local.rs` 的
有界 worker 适配，最多八个排队或执行中的操作，容量保留到实际文件工作结束。
准入前取消阻止迟到修改；准入后取消不回滚已开始的操作。既有文件行为和错误继续
复用同步领域实现。插件调用保留授权后立即执行的边界，不进入这个原生队列。

原生 `hosts_snapshot` 和插件 `hosts.snapshot` 复用同一有界主机读取服务，最多准入
四个实际 worker，包含已排队的 worker。放弃回复不释放仍在执行的 worker 容量或存储
所有权。数据库争用在该 worker 上轮询，等待时不保留插件 policy。等待期间和数据库
锁释放后检查取消及原插件身份与权限；单锁读取分组和主机期间只做无锁取消检查。
正在执行的 SQLite 语句不会被抢占。原生/插件字段和查询错误保持不变；稳定本地
`hosts.list` 适配器保留独立的公共投影与错误契约。这不表示主机写入或全部数据库
消费者均已改为后台执行。

## 自动化证据

`scripts/ci/check-core-contract.mjs` 检查历史稳定插件契约。
`scripts/ci/check-local-api-contract.mjs` 依据有限稳定声明、发现 Schema 和不变的
历史夹具校验实际本地域生产者输出。`src-tauri/tests/automation_cli.rs` 启动真实控制台及桌面 CLI 子进程，
对接固定的 v1 协议夹具。这些检查不能替代真实桌面服务联动、跨平台安装包及升级
验收。

公开包 CLI 验收还会将每个 1.0 候选及之后安装包实际输出的接口发现，与冻结的
本地 v1 基线对比，涵盖方法元数据、输入／结果 Schema、传输和错误。此前的 0.x
安装包仍可用于升级源验收，但不据此声称它已包含稳定声明。包验收报告会记录
是否验证了稳定基线，不能仅凭七个方法调用成功来确认稳定契约。
