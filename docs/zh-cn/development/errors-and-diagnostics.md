# 错误与诊断

在负责处理失败的边界捕获错误。翻译、记录、通知是独立操作，翻译错误不得产生写日志的副作用。

## 前端边界

- `normalizeError` 归类错误，`translateError` 生成本地化文案，两者都不写日志。归一化对象可能
  包含用于特定界面的原始消息、详情或堆栈，不要直接将整个对象写入日志或复制。
- `reportError(domain, operation, error)` 可在没有界面时记录故障。`captureError` 返回归类结果
  和安全诊断；`notifyError` 直接将同一条诊断附到 Toast；`presentError` 用于兼容只接受字符串的界面。
- 应用 IPC 使用 `diagnosticInvoke`，在调用方转换或忽略拒绝之前记录失败。它记录命令名而非参数，
  并重新抛出原异常。诊断传输自身不能使用此包装。
- 可独立恢复的视图使用渲染边界；尽量让导航和输入留在边界外。处于移动交接阶段的面板应向上
  传播失败，由所有者拒绝交接，而不是接受损坏的视图。
- WebView 全局监听和 React 处理器记录未捕获异常。持续重试的后台读写应按故障区间采样：
  记录首次失败，避免重复错误把其他诊断挤出缓冲区。

## 原生边界

`AppError` 序列化仅保留现有传输格式。自动更新、生命周期清理、原生窗口和事件发送等直接
消费错误的操作，应在该边界调用 `diagnostics::failure::native` 或 `observe_tauri`。
使用固定领域和操作名，不要把外部错误原文、路径、负载里的 ID、SSH 数据或命令参数放进标签。
如果错误会返回到已记录失败的 IPC 边界，无需在 Rust 中再记一次。

审查忽略的结果时，区分预期取消或销毁、已由返回 Promise 观察的队列尾部、幂等清理及实际资源
故障。不要隐藏回滚失败，或把可重试失败当成成功。回滚不完整应与原始失败分开记录，不改变
资源归属及重试决策。

## 输出与隐私

结构化故障记录包含事件编号、时间、严重级别、固定操作与类别、白名单标签以及可用的应用相对
源码坐标。不记录任意异常原文、原始 IPC 负载、终端输入、私人文件路径或原始堆栈。
预期取消通常是 debug，I/O、运行时、数据库和 SSH 故障通常是 error。

诊断命令不授予通用日志写入或读取权限。日志为尽力写入、受本地级别过滤器约束，收到回执并
不表示已落盘。目录、写入器或 IPC 不可用时，近期故障留在有界内存缓冲区。输出按事件编号
合并同一事件、优先显示磁盘副本。诊断写入失败不得递归重试。用户侧排查及保留规则参见
[日志指南](../guide/logging.md)。

## IPC 诊断定位字段

`diagnosticInvoke` 记录具体子动作（例如 `panel_window_control.stagedModel`），以及 `ipc` 中的命令、子动作、面板类型、租约代次和耗时。插件调用保留命令标识，不保留输入或运行时令牌。
固定的迁移／模型／视图校验原因通过前后端白名单保留，避免全部变为 `Operation failed`。事件ID仍关联Toast、详情与输出。读取与提交竞态由读取层复核新快照；已退役请求无需提示用户，仍有效的请求失败继续报告。
