# 交付追踪

本页是当前 rollout 的长期交付台账。工作合入、CI 完成或 Release 公开后应及时更新。Issue #468
仍是详细验收记录；本页用于让贡献者无需翻查长评论历史即可看到优先级和发布门槛。

## 执行规则

- 状态统一使用 `已完成`、`进行中`、`受阻`、`待开始`。只有精确 head 的必需 CI 通过并记录
  验收证据后，PR 才算完成。
- P0/P1 问题阻断发布；主流程可用时，P2 精修可以留到后续版本。
- 每完成约一至三个连贯功能发布一次 Beta。正式版必须绑定同产品源码、已发布且明确验收的 Beta。
- 开发继续期间，自动生成的 `release/dev-to-main` PR 保持 Draft。只有最终审查过的 head 才转为
  Ready for review，并由该操作启动准确 head 的 PR CI。
- 任何必需验收项未完成时，不得关闭 Issue #468，也不得宣称 rollout 已完成。
