# 开发与交互规范

以下规范适用于内置功能和插件贡献。这里只保留长期约定；临时计划、截图和交接记录放在
`.tmp/`，不要混入正式开发文档。

## 产品与展示

- 在既有设计上渐进精修。能用层次、间距、对齐的小调整解决时，不做大范围视觉重构。
- 复用公共控件包装与主题 token；长文字不得挤压开关或图标。使用已有连续曲率圆角及
  平台回退，不另造不一致的圆角数值。
- 默认面板使用内部组合基础组件的综合工作台容器。业务只提供一份正文，不独立维护
  小窗版与停靠版。特殊场景可以直接组合基础组件，但不要求每个调用方重复组合。
- 同类操作相邻：新建靠新建，刷新和更多操作靠后。清楚区分标题、分组、内容行和操作。
- 空间紧张的对话框将普通解释放入文字旁的问号 tooltip；宽裕的设置页可以展示小字。
  安全同意、破坏性后果、校验错误和恢复步骤不能只藏在 tooltip 中。保证键盘、焦点和
  Escape 的关闭顺序。
- 密码显隐放在输入框内的小眼睛上；选择工具尽量与底部操作同排，避免多占一整行。
- 原生滚动、文本鼠标光标、编辑器选择与撤销、行号、中英文等宽网格和输入响应是基础
  体验，不是可有可无的装饰。

## 所有权、资源与 API 覆盖

- 展示切换只移动视图，不应重新连接 SSH、重启插件、重复后台任务或丢弃草稿。业务资源
  保持唯一所有者；隐藏与停止、断开必须区分。
- 复用公共布局和指针控制。每帧最多预览一次，松手再持久化，中断则回滚；相关分隔线
  在各自所有者中批量提交，不通过重挂载正文实现缩放。
- 内置能力应有可发现、受权限保护的插件 API，不做临时私有接线。能力发现不等于授权；
  已公开的冻结契约保持不变，新能力单独增加版本或实验接口。
- 宿主管理的连接、共享规则不属于某个插件界面的生命周期。插件 Bus 不能传递对方权限，
  不可信消息也不能作为授权依据。
- 原生窗口身份和运行时代次是安全边界。不得为了增加 WebView 删除 main-only 检查或
  重复整套 bootstrap；跨 WebView 迁移必须明确所有权、取消和回滚。
- 不把明文密码、私钥或秘密草稿写入布局和日志；涉及凭据的操作保留明确用户确认。

## 交付与协作

- 使用隔离分支、worktree 和可审查的 PR，不覆盖脏的兄弟仓库或无关用户改动。确认合入
  且不再需要后，才清理过期分支和 worktree。
- PR 按顺序逐个合入；精确 head 的完整 CI 全绿后再合并，保留 PR 记录及开发分支线性
  历史。其余 PR 更新基线并重测。合并、发布前解决已知 P0/P1；非阻断 P2 精修单独
  跟踪，后续小版本迭代，不为追求无瑕疵而拖延可用主流程。不绕过失败检查。
- 约完成一至三个连贯功能发布一次 beta，需求全部完成后再发布最终验收 beta。使用自动
  不可变发布快照流程，验证各平台构建、资产、签名和更新元数据；beta 不代表正式验收。
- **正式版必须绑定已发布、同产品源码且明确验收通过的 Beta。** 只有维护者在 Beta
  合并前应审查生成的正式版 PR、该准确 head 的 CI 和最终安装包／升级验收证据；不再
  要求已发布 Beta 或额外的 Release 验收标记。
- 中英文开发文档和 UI 翻译保持一致。明确记录真实限制，不把部分实现标为完成。
- 除非维护者明确修改允许列表，编码 subagent 只可使用
  `deepseek-ai/DeepSeek-V4.1-Flash`；不可用则直接开发，不得静默改用其他模型。贡献者
  实现并按审查修改，协调审查者对审查、合并和发布负责。

- 所有内置面板及页面都应支持小窗，只有插件贡献视图可以声明不支持。移动或
  隐藏不能断开会话；显式关闭最后一个普通连接消费者遵循默认开启的关闭断连
  设置，转发与挂载规则专用连接不受普通面板关闭影响。
