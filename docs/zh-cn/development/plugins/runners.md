# 持久远端运行器

实验性 `runners.*` API 使用用户明确部署的原生 helper 和指定的运行时。部署需要原生确认及新的远端目录，不安装系统服务，也不会隐式选择 Node。

记录归属于插件及捕获的目标身份，不依赖临时 SSH 会话 ID。新部署会保存主机 ID、实际连接地址和握手时观测到的主机密钥，新连接必须三者均匹配，才能读取原任务日志或停止任务。修改保存的主机或信任另一个密钥不会悄悄改变恢复目标。断开 SSH 或关闭 Tunnelde 会保留已确认运行的任务；恢复不会重复启动任务、发送提示词或消息。

停止任务、退休插件运行时或取消未完成的启动时，先保存停止意图，再尝试远端清理。原会话断开时，`runners.stop` 仍可保存意图并返回 `stopRequested: true`、`status: "stopping"`，仅表示收到请求，不表示进程已经退出。后台清理通过可用连接按并发上限及退避重试，重连后和受限模式下也会继续；其独立额度不会占满前台操作空间。

只有观察到 helper 的终止状态，才清除停止请求。若启动响应丢失，状态仍不确定：一次 `notFound` 不能证明延迟启动以后不会执行，因此记录会保留到后续观测能够确认结果。重复操作可能返回 `plugin.runners.busy`，调用方应等待并继续查询，避免自动新建替代任务。停止确认前禁止发送新消息。

元数据采用有界读写、原子替换及修订比较，延迟响应不能覆盖更新的停止意图；等待 SSH 时不持有记录锁。私有修订及启动状态属于存储细节，`runners.list` 的既有公开结构保持不变，缺少新字段的历史记录仍可读取。

这些生命周期规则不代表 runner API 已稳定，也不替代活跃资源句柄、不授予其他插件的权限、不验证供应商账户配置。远端部署、初始化与凭据仍需相应授权。

## 部署中断

远端修改前，宿主先持久保存部署预留及阶段：发送 `MKDIR` 前记录创建意图，收到目录创建确认后才开始上传，全部文件成功关闭且再次通过授权检查后才标记就绪。插件内容来自与已授权指纹一致的有界字节快照；所选原生 helper 上限为 64 MiB，插件快照上限为 32 MiB。上传采用排他创建，并拒绝与原生 helper 保留路径冲突的插件包。

原生恢复页面区分尚未提交的预留、目录创建待确认、上传未完成和部署就绪。未完成部署不会出现在 `runners.list` 中，不能满足 `runners.start`，也不能被 `runners.deploy` 复用；复用会返回 `plugin.runners.deploymentIncomplete`。已有就绪记录和公开列表字段保持兼容。只有尚未提交远端修改的预留可经原生确认移除；整条记录核对可防止延迟确认删除已进入后续阶段的部署。

断线或重启不会将未完成记录变为就绪。重连后路径存在，既不代表归属已确认，也不能说明丢失响应的修改已经结束。请使用全新目录重新部署，并保留恢复记录供检查。软件不会递归删除部分部署目录。部署与配置文件的安全核对和清理仍是独立恢复操作；存在日志不等于远端残留已清理。

## 初始化配置

`runners.startInitialized` 是独立的实验性方法。部署前通过 `api.describe` 查询，
不能向旧的 `runners.start` 添加一个可能被忽略的参数来选择新模式。插件通过
`"remoteRunner": {"configuration": "initialize-v1"}` 明确声明支持，并声明
`ssh.exec` 权限。宿主从与已批准指纹一致、实际用于上传的同一字节快照读取声明，
将其绑定到部署记录。未声明支持的历史部署不能使用新模式。

参数为 `{sessionId, directory, configuration, secrets?}`。配置必须是至多 200 KiB
的对象，秘密是字符串映射；完整 RPC 仍受宿主 256 KiB 请求上限约束。预留任务前，
宿主查询记录中的辅助程序，要求其明确支持任务协议 1 及
`runner.initialize-config.v1`。查询失败或不支持时不会回退到配置文件；查询后重新
核对授权、原目标身份和完整部署修订。

辅助程序通过 stdin 接收有界的版本 1 信封，命令行明确选择
`--bootstrap initialize-v1`。配置值和秘密不进入命令参数或宿主任务记录。输入须在
10 秒内结束，完整验证后才创建任务目录。子插件以 `--initialize-config` 启动，
在 initialize 请求中接收 `configurationTransport: "initialize-v1"`、
`configuration` 和 `secrets`。辅助程序存储默认为空，不再以配置播种。插件仍可
主动保存数据；传输协议不能保证任意插件代码、所选运行时或系统崩溃处理永不落盘。

启动确认、停止意图与重连恢复复用现有修订状态机。中断启动保持待确认，不会重放。
旧 `runners.start`、文件配置和历史任务仍可使用；新模式不会清理历史残留。

## 启动结果未知时关闭启动许可

新 `runners.startInitialized` 任务还会协商所选 helper 的
`runner.admission-fence.v1` 能力。宿主先保存私有任务令牌，确认登记成功后才提交
一次带保护的启动。完整配置输入验证后才消费启动许可，因此等待输入期间取消可阻止
迟到启动创建进程。公共 RPC 和插件清单无需新增字段，公开快照不包含令牌。

停止和状态回执必须绑定任务与令牌，使用支持的版本和状态，成功退出，并在合计
4096 字节输出内。宿主重新核对原 SSH 目标和整条本地记录。只有已关闭启动许可且
`notFound` 的有效证明，才能确认未知启动不会发生；普通 `notFound` 仍不够。
关闭仍在运行任务的启动许可不代表进程退出。重连只重试停止和状态查询，插件已卸载
时仍可处理此前保存的停止意图。

helper 保留有界私有登记日志和合作文件锁。每个部署最多 4096 份日志，每份最多
1024 字节；达到上限拒绝新登记，不淘汰取消证据。损坏、不完整写入、链接和不支持的
锁需要检查，登记缺失会阻止启动。此契约要求合作命令共享同一私有部署，文件系统
遵守锁与刷新语义；任意替换命名空间、磁盘回滚及断电保证不在范围内。迟到命令仍
可能存在时，不得删除这些回执。

支持初始化但不支持该能力的旧 helper 继续使用原传输；已有任务不会因为更新了 helper
就被自动认定具有启动保护。登记回执不确认历史 SFTP 写入结束，也不授权清理。

## 文件配置写入中断

新任务独立记录配置阶段：尚未提交、创建待确认、写入未完成和已保存。文件采用排他创建，
在 OPEN 时指定 0600 权限，不截断已有文件，也不在写入后按路径修改权限。有界写入器在
各数据块之间、关闭后及提交启动前重新检查授权与整条任务修订。更新的停止请求可阻止
延迟写入响应继续启动任务。恢复不会重新写入配置。

原生恢复界面展示这些阶段，不展示配置内容或秘密。任务返回 `notFound` 或已停止，不能
证明未知 OPEN、WRITE、CLOSE 已结束；这类恢复记录不能移除。配置已保存不代表进程已启动
或残留已清理。明确移除符合条件的终态记录会保留远端文件。历史记录仍可读取，不推测其
配置状态；`runners.list` 与所选 helper 的协议保持不变。

## 恢复与插件版本变化

在**设置 → 插件 → 远端任务恢复**中查看保存的记录，包括已停止或卸载插件留下的记录。宿主无需启动插件或选择 Node 即可检查状态、保存停止意图。每页显示 32 条。保存记录或 SSH 已连接不代表任务正在运行，远端观测会显示检查时间；离线、目标变化、目标歧义和待核对身份分别展示。

**打开远端文件**会在常规文件浏览器中打开记录的部署目录，并在已记录配置准备时展示
推导出的配置文件路径。优先复用匹配原目标且由用户管理的 SSH 连接，不借用插件专属或
端口转发专用连接。没有可用连接时，使用正常凭据与信任窗口，为原保存主机建立独立的
后台连接。在目标认证前核对已捕获的地址与主机密钥，修改主机或信任其他密钥不能将
本次操作转向新目标；打开前会再次核对整条恢复记录。取消或关闭恢复页会释放尚未接管的
连接，遗留请求在 15 分钟后过期。已接管连接由用户管理，插件停止、卸载及进入受限模式
不会关闭它。该入口不自动删除文件，也不证明残留归属；常规文件浏览器操作仍保留原有行为。

历史记录未捕获目标身份，仍可读取，但检查与远端清理前必须通过原生确认核对原地址和主机密钥。同一保存主机存在指向不同目标的连接时，宿主拒绝猜测。核对不能覆盖已绑定身份。若旧记录已有停止意图，绑定原目标后可能立即恢复该清理请求。

更新插件不会自动将旧任务交给新版本。**交接控制权**要求当前已安装插件已有 `ssh.exec` 授权，并对这条任务进行原生确认。它保留原部署、代码与权限范围，不清除停止请求、不启动任务、不发送提示词、不重放审批。已确认结束或有待确认停止请求的任务不能交接。

实验性 `runners.review` 接受 `{sessionId, runnerId, directory, kind: "destination" | "control"}`，返回 `{reviewed: boolean}`。`destination` 仅绑定待核对的旧记录；`control` 将一条任务交给当前已授权插件的指纹。取消返回 `false`；记录变化、撤权、连接变化或确认过期均不会提交更改。调用前通过 `api.describe` 确认方法是否可用。`runners.list` 保持既有字段，不暴露私有身份和所有权信息。

任务记录只有已确认终态且无停止请求时才能移除；远端文件保留。未知启动返回 `notFound` 不满足此条件。原生操作使用绑定整条记录的不可读令牌，并在确认后重新核对，旧页面无法删除或修改更新后的记录。

## 辅助程序能力查询

展开恢复记录后，**查询辅助程序能力**只会查询经过原目标身份验证的已记录辅助程序。
部署就绪后或已有任务记录均可查询，无需启动插件。查询只传入 `--capabilities`，
不附加任务或配置参数，时限为 5 秒，stdout/stderr 合计限制为 4096 字节，
不会自动下载或选择其他辅助程序或运行环境。

结果分别显示辅助程序版本、任务协议和声明能力。超时、传输失败、输出超限、缺少
退出状态、非零退出、元数据无效以及协议不兼容各有明确提示。查询被拒绝不能证明
辅助程序属于某个旧版本，原有状态查询和停止操作仍然可用。未知但有界的能力仅供
展示。查询不确认任务、配置写入或部署已结束，不转移资源归属，也不允许删除残留。
结果不持久化，记录变化后作废。

信封版本及兼容规则见辅助程序仓库的 `docs/zh-cn/development/capabilities.md`。
这是原生恢复功能，公共 RPC 和稳定插件契约不变。

## 原生残留元数据观察

原生 `runner_recovery_action` 新增接受 `artifacts`。本阶段只提供 API 基础，
不新增界面按钮或公共插件 RPC。它要求整条恢复记录令牌与原 SSH 身份一致，
任务配额租约覆盖能力查询与元数据观察。每次等待远端观察后，包括失败结果，
都重新核对记录与目标，才允许下一次请求或返回结果。

仅采用初始化传输、有原始登记令牌且无历史文件配置阶段的任务适用。旧任务返回
`unsupported/legacyTask`；所选 helper 未声明残留能力时返回
`unsupported/helperCapability`，传输与有界解析失败分别保留。不会自动下载、
选择或更新 helper；已发布的 helper 0.27.0 尚无此能力。

返回的可选临时 `artifacts` 包含恢复令牌、检查时间和结果。观察结果具有可空
登记状态、`consistency: "pointInTime"`、`cleanupAuthorized: false`，及目录
缺失/存在/不可用快照。存在快照仅包含已知固定名称、类型、十进制字节数字符串
及其他直接子项数量，不包含任意文件名、路径、登记/请求令牌、正文、原始 stderr
或带凭据的诊断。最多枚举 256 个子项，stdout/stderr 合计不超过 16 KiB，观察
请求时限为 12 秒。

目录缺失也不代表进程、启动、配置写入或文件修改已结束，更不证明残留归属或
可以安全删除。观察不会修改恢复元数据、删除远端文件或允许移除未知历史写入。
明确且持久的补偿仍是独立待办。请求/回执及非原子文件系统一致性边界见 helper
仓库 `docs/zh-cn/development/runner-artifacts.md`。
