# 插件概览与兼容性

[English](plugins-overview.en-us.md) · [插件开发详细指南](plugins.zh-cn.md)

Tunnelde 支持独立分发的扩展，扩展可以提供命令、视图、主题、文件图标和预览等能力。
可以在插件市场浏览扩展，也可以在插件侧栏从本地文件夹或 ZIP 安装。每个扩展会说明
自身能力、所需的软件版本和权限；市场中的扩展会随时间变化。

按 **F1**，输入 `>`，即可搜索已安装扩展提供的命令和视图。显示命令列表不会启动扩展；
执行代码时可能需要授权。使用系统已有的 Node 运行时前，Tunnelde 会先征求同意；
声明式扩展和主题包不需要 Node。Tunnelde 插件不等同于 VS Code 扩展，通常无法在没有
兼容扩展宿主的情况下直接运行 VSIX。

## 信任与数据访问

请查看每个扩展申请的权限。可执行插件在独立进程中运行，但获得广泛权限的受信任插件
仍可以执行影响较大的操作。受限模式会禁用插件执行和宿主能力访问。插件权限、运行时
同意和 SSH 主机密钥验证是不同的决定；插件权限不会直接授予已保存 SSH 密码或密钥的访问权。

## 面向宿主开发

[插件市场仓库](https://github.com/TunneldeDev/tunnelde-hub)提供 SDK、TypeScript
声明和生成的方法目录。插件清单包含 `apiVersion`，也可以声明 `engines.tunnelde`
版本范围；宿主运行前会检查两者。`api.describe` 可查询当前宿主的方法，调用时仍需
遵守权限和审批要求。

`apiVersion: 1` 标识当前协议，并不意味着所有方法、数据或界面状态字段都已承诺稳定。
`api.describe` 会为每个方法返回 `stability`：`stable` 表示兼容性承诺，`experimental`
表示小版本间仍可能变化，`deprecated` 会同时提供迁移说明。稳定方法还会在 `since`
中标明首次支持的宿主版本。尤其是设置、工作区布局、聊天、远端运行器和高级面板接口
仍可能变化。请避免依赖未记录的字段，检查能力并处理错误。旧 SDK 示例与宿主可能存在
差异；请结合 SDK 自带的方法目录和目标宿主的 `api.describe`，不要依赖固定的方法数量。

CI 也会使用当前宿主加载固定保存的 v0.28.0 示例插件，并运行其 JSON-RPC 生命周期。
这只覆盖一个历史插件的通信和视图响应，不能证明所有 API、权限或存储数据均兼容。

`sessions.list` 和 `sessions.connect` 的响应使用独立的插件会话数据结构，保留现有
API v1 字段：`id`、`hostId`、`title`、`address`、`cols`、`rows` 和 `connectedAt`，
不再直接暴露 SSH 管理器的内部类型。这一步尚不表示这些方法已稳定，也不保证连接生命
周期和错误行为的兼容性。

应用和市场可以独立发布。请将最低应用版本设置为支持插件所有功能的首个版本，并在该
版本上测试。详细指南介绍当前的扩展声明与权限模型。
另请参阅 [API 兼容性与安全](plugin-api.zh-cn.md)。
