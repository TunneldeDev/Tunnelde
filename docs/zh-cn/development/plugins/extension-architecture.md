# 插件扩展架构

[English](../../../en-us/development/plugins/extension-architecture.md) · [API 兼容性](api.md)

扩展按领域组织，以契约、运行、数据、表现、行为、治理六层检查能力。
这是架构建设方向，不表示所有领域都已具备六层完整能力。

## 接口代码组织

接口先按主机、文件、终端、转发等领域分目录，再按契约、服务编排、持久化、传输适配和
表现层的实际职责分文件。六层用于检查能力是否完整，不要求每个小模块机械创建六个文件。
公共基础设施只承载领域无关的事件、资源作用域和同步机制，不集中存放各领域业务。

转发领域的协议结构与校验在 `services/forwarding/contract.rs`，持久化在同目录的
`repository.rs`，SSH 启动校验在 `runtime.rs`，服务入口在 `mod.rs`。原生 IPC 在 `commands/forwarding.rs`，插件适配在
`plugins/api/domains/forwarding/mod.rs`，SSH 监听与转发实现保留在传输模块。两类适配都调用领域服务。
前端同样区分领域契约、共享状态和视图。目录调整不改变已有 RPC 名称、权限或返回结构。
后续 SDK 和文档按领域提供入口；旧目录尚未全部完成迁移。

RPC 边界 `plugins/api.rs` 负责请求授权、大小限制及响应返回前的再次授权。
`api/routing.rs` 只选择适配器，并保留已提交操作的领域失效通知。
具体适配在 `api/domains/<domain>/`；文件领域再区分本地操作、SFTP、有所有权的传输和
文本原子保存，连接的协议结构与有界 SSH 命令执行也分别存放。
前端命令的请求与响应桥接在 `api/transport/frontend.rs`，不与领域业务混写。
测试靠近所属实现，跨领域冻结契约的样例继续共享。这些内部模块路径不是新的插件 RPC 命名空间。

公开 UI 类型在 `src/lib/extensions/contracts/<domain>/`，市场仓库中的 SDK 镜像及
RPC 类型声明也按领域组织。兼容入口仅重新导出历史名称，生成工具校验公开依赖图及
历史消费者；不要把应用私有状态容器直接复制到 SDK。

宿主 UI 桥接也在 `src/lib/extensions/` 下按领域分类：`files/context.ts`、
`terminal/bridge.ts`、`history/context.ts` 分别负责数据适配，各领域的 `provider.ts`
负责带授权检查的回调接口。共享租约及访问类型在 `runtime/providers/`。
`ProviderSurface` 负责选择渲染器、检查当前身份及恢复内置视图，不承载领域操作实现。
这些私有模块不是新的公开 SDK 入口。

原生转发功能中，`model/` 放 DTO、保存载荷及地址工具，`data/store.ts` 负责共享失效，
`runtime/useForwardingController.ts` 编排操作，`components/` 放列表和编辑器。
页面组合这些职责，编辑期间保持控制器挂载。实验性转发提供者使用
`contracts/forwarding/` DTO 与领域专用快照、授权和 UI 桥接。
原生 `plugins/forwarding/` 适配进一步拆分授权、作用域生命周期、连接获取和规则动作，
复用领域 CAS 持久化及监听最终提交。[转发契约](ui.md#端口转发表现提供者)
说明其所有权和兼容性限制，其他领域迁移仍未全部完成。

## 发现已实现能力

通过 `api.describe` 查询实际 RPC 方法、权限及稳定契约。该目录包含
`extensions.describe` 时，可调用其实验接口查询已实现的 UI 扩展点。
结果包含版本、稳定性、六层标识、领域及 RPC 命名空间，以及扩展点的 ID、领域、
层级、稳定性、组合规则、注册方法、所有权、权限和配额。未知字段和类型应视为
未知能力，不应据此推断授权。

当前扩展目录列出主机装饰、主机菜单、底栏项目和标签栏控件。`composition: "merge"` 表示
多个所有者按该扩展点规定的顺序组合；`ownership: "runtime"` 表示贡献绑定插件的
已批准运行实例，不是持久化应用数据。领域命名空间分类实际方法，不表示已开放
公共依赖注入、完整领域服务、远端执行或相应权限。测试会核对目录引用与实际方法、权限。
清单贡献使用 `registration.manifest` 和 `ownership: "manifest"`，可在启动获准的运行时前显示元数据。
[主机菜单命令](host-menu.md)与文件菜单共用授权、目标失效检查和输出处理。

[主机装饰](host-list.md)、[底栏](status-bar.md)和
[标签栏](tab-bar.md)使用共享运行时所有权注册表。前端先订阅再读快照，
按修订同步，卸载时释放监听；授权变化后隔离排队的旧读取和事件。
该机制不依赖某个具体视图或 Zustand store。

## 运行时资源所有权

前端内部资源作用域管理订阅与异步工作。`use` 注册已有清理操作，`acquire` 在打开资源前
预留配额并持有清理操作，`run` 在工作结束后释放预留。获取资源或执行工作时可指定调用方
取消信号与超时。父级取消或作用域释放后，调用者及时收到失败，即使底层操作不响应取消，
也不必继续等待；晚到的资源会被清理，不再交付。取消不代表撤销原生或远端已经产生的效果。

被取消的底层工作实际结束前仍占用配额，未完成的异步清理也占用配额，防止反复重试在
限制之外积累工作。资源获取成功后归作用域所有，获取阶段的超时和调用方信号不再关闭该资源；
作用域释放资源时会中止其获取信号。

释放操作幂等，先中止生命周期，再按注册的逆序启动清理。同步或异步清理错误会被观察并报告，
但释放操作不等待异步清理，也不能强制不响应取消的工作结束。作用域默认配额为 128，
无效配额和超时在启动工作前拒绝；关闭、调用方取消及超时使用不同错误码。

主机装饰、底栏项目与标签栏控件同步已使用此机制。监听初始化和每次快照读取的超时均为
30 秒。读取超时后仍保留订阅，后续刷新可以恢复，过期读取不能覆盖当前内容；初始化失败会
清理部分成功及晚到的监听。这些作用域也支持实验性 UI SDK，但不能为直接加载的前端代码提供沙箱隔离。

## 领域边界

RPC 方法发现声明按领域放在
`src-tauri/src/plugins/api/catalogue/<领域>/methods.rs`，组合模块仅负责目录元数据与组装。
路由、授权、领域服务、持久化和 SSH 传输分别承担各自职责。原有协议方法名、权限及兼容
元数据保持不变。历史目录样例逐方法比较完整契约，发现结果的展示顺序不作为契约。
SDK 读取器检查全部组合领域，拒绝未知条目、重复方法、缺失文件和未引用的领域。

方法发现声明、RPC 适配器和 SDK 类型已在各自层内按领域分类，原有 SDK 入口保留兼容导出。
UI 声明单独位于 `src/lib/extensions/contracts/<领域>/`。这些源码分类不表示所有领域的
服务和扩展能力均已完成迁移。

公开数据采用协议 DTO，不任意暴露内部状态。操作经领域服务执行，并在执行时
再次授权。插件执行位置与目标资源位置分别表达。取消、撤销、补偿和原子事务
采用不同契约；被取消的远端操作可能已经产生效果。

保存的主机和分组已由应用命令与插件 RPC 共用同一个原生领域服务。服务负责输入
规范化、持久化、会话名称同步、凭据清理、审计记录与提交后的失效通知。删除主机与
保存的连接路由使用同一个数据库事务，主机排序也采用原子事务。写入失败不发布成功
通知，也不清除凭据。现有 RPC 的请求和返回结构保持兼容。这是首个已抽取的领域，
不表示所有原生命令已经完成迁移。

每个扩展点明确贡献是合并、选择提供者还是替换视图；优先级不能解决所有冲突。
视图/工作台提供者以及既有快捷键冲突遵循用户选择。插件存储及附加数据字段
使用插件命名空间和 Schema。

## 可信前端组件

实验性 [UI SDK](ui.md) 加载用户明确批准的本地 ESM 模块，共享宿主 React
和公开组件。模块声明 SDK 版本范围，注册清单声明的组件视图和命令。批准绑定包快照
和运行代次；停止或撤权后清理所有者贡献并拒绝旧地址和调用。

前端代码共享宿主 JavaScript 上下文及原生桥，是可信代码，不是沙箱；错误边界无法
打断死循环或撤销任意副作用。宿主保留授权、凭据和恢复界面。完整工作台替换及其他
领域迁移尚未完成。

既有稳定 RPC 契约保持兼容，扩展目录、主机装饰和 UI SDK 为实验接口。扩大稳定范围
需要完成 SDK 同步、旧插件回归和真实平台验收。

## 领域文件边界

新增接口先按功能领域分类，再按实际职责拆分文件或子目录：公开数据契约、生命周期与运行、
存储或投影、界面适配、业务操作及治理。不得将无关领域塞入同一命名空间，也不得在 SDK
聚合入口内累积业务实现。有需要时继续分层，不建立空的六层目录来代替架构。
公共外壳只协调提供者；业务归领域服务所有。消费者依赖公开契约，不引用其他领域的内部
状态或私有组件。兼容入口保留既有符号的重新导出；市场 SDK 按公开依赖图镜像生成。
[监控领域](monitor-ui.md)说明了一种具体组织方式。

[运行资源生命周期](runtime-resources.md)说明实验性的自有资源观测、释放及其边界。
