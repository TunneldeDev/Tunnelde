# 应用更新

[English](../../en-us/guide/updates.md)

在**设置 → 更新**中检查新版本、查看变更并下载或安装。更新操作直接位于设置内。
所有安装默认选择**正式版**渠道；**公测版（Beta）**渠道也会接收版本更新的公测包。
开发快照不作为软件内的更新渠道；旧设置中保存的开发渠道会迁移为正式版。
切换渠道不会强制降级当前版本。

## 查看版本之间的变更

检测到更新后，展开**更新说明 · 当前版本 → 目标版本**。软件会加载比当前安装版本新、
且不高于目标版本的公开发布说明，并按语义版本从新到旧排序，不受 GitHub 展示顺序或
发布时间影响。

正式版渠道仅列正式版，公测版渠道同时列正式版和公测版；排除草稿、开发快照及无关标签。
已删除的发布和未公开的说明无法还原。默认展开目标版本，其余版本可以单独展开阅读；
折叠版本不会渲染 Markdown。

历史说明使用**网络设置中的应用更新代理**，仅在展开时加载，多个设置面板共用加载结果。
历史加载独立于更新检查、下载和签名验证，失败不会禁止安装。
切换更新源、渠道、目标版本，或完成新一次检查后，原来的历史选择会失效。

GitHub 历史暂不可用时，会保留目标说明和已经加载的页面，明确提示内容不完整，并提供
**重试**。只有读完全部公开页面且找到目标版本，才会标记历史已完整加载。
加载最多持续 25 秒、读取 10 页及 8 MiB 响应，展示最多 200 个相关版本和 1 MiB 说明文本；
达到限制会提示内容可能不完整。

## 更新源与安装

默认更新源为 GitHub。自定义 HTTPS 源需要在路径中包含一个 `{channel}` 占位符，
并提供兼容的 Tauri 清单与已签名安装包；修改地址后先应用，再检查更新。
自定义源目前仅提供目标清单内的说明，不会混入来自 GitHub 的其他版本历史。

所有更新源都保留相同的安装包签名校验。检查时选中的安装包会保留给安装操作，
更新说明无法改变下载地址或验证公钥。安装会重启应用；不支持自动安装的平台会提供
手动下载入口。

Windows 安装器自动使用支持的系统语言，否则使用英语；内含英语和简体中文。
安装与更新不会停在单独的语言选择弹窗。应用界面语言可在设置中独立修改。

发布与镜像要求见[发布维护说明](../development/releases.md)。

## 连接失败与请求限流

公测版先通过 GitHub API 查找适用版本，失败后自动尝试公开的 Atom 发布源。
正式版直接请求最新正式版的更新清单。所有请求均使用**设置 → 网络与代理**中的
**应用更新**路由；TCP 代理测试成功不代表所有 HTTPS 发布或下载入口都能访问。

API 和公开发布源均依赖 GitHub；GitHub 或网络故障时，回退不等于使用独立镜像。
收到 HTTP 502、503、504 时，只在原请求剩余时间足够的情况下，使用相同来源和代理
自动重试一次，不延长原有请求时限。限流、鉴权失败和不存在的资源不会自动重试。
持续超时或网关故障时，应检查应用更新代理、稍后重试，或选择可信的自定义更新源。
响应正文读取失败会保留已知来源，并标记为 `response-body` 阶段，避免底层错误缺少
URL 时被误判为自定义更新源。
直接检查与公开源回退中的更新清单均使用 25 秒请求时限，避免较慢的安装资产重定向
沿用发布列表的 12 秒时限。API 发现和公开源回退分别最多持续 22 秒和 38 秒，仍受原有
65 秒整体检查时限约束。

检查失败时，更新设置会分别列出失败来源、原因、HTTP 状态码和服务器提供的限流重试时间。
API 限流期间再次检查仍会尝试公开源，暂时跳过同一代理出口的 API；修改应用更新代理
后允许立即尝试新的 API 请求。限流记录仅保留在当前进程内，不会修改系统代理。
无法访问更新源不会被当成“已是最新版本”。

错误通知的**查看更新详情**打开更新设置；**配置应用更新代理**和**打开输出日志**提供
后续处理入口。详细诊断仍写入本机每日日志，记录来源、请求阶段、HTTP 状态、允许公开的
限流响应头及脱敏后的连接原因，不记录代理密码或自定义源 URL。日志中的依赖源码路径
可能属于构建机器；不需要在用户电脑上创建该路径。

更新清单由宿主限量读取，再交给 Tauri 进行平台与版本选择；安装包继续使用应用内置公钥
及带版本的签名验证，网络诊断不会放宽验证规则。
