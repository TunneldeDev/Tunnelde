# 原生板块 API 覆盖

新增原生交互时，先明确同一领域服务是否支持读取、修改、观察、取消，以及各动作的授权条件。指南不是运行时能力声明；用 `api.describe` 和 `extensions.describe` 检查实际安装版本。

| 板块                               | 读取 / 修改                                             | 观察 / 取消                                                 | 后续核对                                         |
| ---------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------ |
| 挂载                               | `mounts.rules.*`、`mounts.groups.*`、`mounts.runtime.*` | `mounts.groups.observe`、`mounts.operations.observe/cancel` | 实机断线恢复验收                                 |
| 插件通信                           | `bus.discover`、`bus.publish`、私有成员操作             | `bus.receive`、`bus.unsubscribe`、请求取消                  | 审查背压及 SDK 兼容性                            |
| 编辑器                             | `editor.readRange`、`editor.applyEdits`                 | `editor.observe`                                            | 补保存、编码切换、撤销和重做，复用编辑器原生动作 |
| 主机、文件、终端、转发、监控、设置 | 参见[板块 API](host-details.md#板块操作与-api)          | 按实际目录核对                                              | 分板块记录 UI 专有操作、权限和生命周期           |

每个新增写动作需测试拒绝无权调用、修改时版本冲突和撤权竞争。事件是刷新通知，丢失后通过快照恢复；需要追踪结果的动作返回可查询的回执，不靠事件确认提交。
