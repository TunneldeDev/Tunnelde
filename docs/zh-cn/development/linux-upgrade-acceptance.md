# Linux 公开包更新验收

`linux-ota.yml` 工作流在一次性 GitHub-hosted Ubuntu 22.04 桌面运行原始公开
AppImage，使用包自带的解压运行模式、Xvfb、Openbox、AT-SPI 及原生生成键盘／指针输入。
不向应用注入脚本，不修改应用包。

PR 只运行环境探针，检查原始资产 SHA-256／大小、离线和实时 CLI 版本，以及实际可见的
Welcome 标签和筛选后的更新命令。可访问性状态可能先于绘制，截图需连续两次识别到
目标控件文字；断言通过后仍须审查实际截图。

手动 `upgrade` 模式只接受已审查的 `v1.2.1` 至 `v1.3.0` 组合，且必须填写
`upgrade-test-only` 确认值。仓库不符、非手动或非 hosted 环境拒绝执行。
先确认工作流注册和准确分支提交，再触发：

```sh
gh workflow run linux-ota.yml --repo TunneldeDev/Tunnelde --ref <已审查分支> \
  -f tag=v1.2.1 -f mode=upgrade -f acknowledgement=upgrade-test-only
```

runner 通过受支持 CLI 写入公共偏好，以原生键盘／指针在原始 GUI 保存合成主机和命名
设置 Profile，再从 F1 执行检查更新，以原生指针点击下载并安装。
下载、签名验证、安装和重启均由应用更新器完成，夹具不会显式启动目标应用。
通过条件包括：安装后 AppImage 摘要匹配准确的目标公开资产、目标版本实时端点自行出现、
全部写入的公共偏好保留、完整公共主机与非空 Profile 记录一致，以及原生正常关闭后
目标端点和进程退出。Profile 检查只以只读模式打开本次规范 SQLite 路径，不直接写库
预置。夹具仅输入 ASCII，不代表物理输入法验收。

矩阵尚未写入非空历史／插件／凭据数据，不证明这些数据的迁移兼容性，
也不代表物理桌面行为或全部历史升级路径。失败保留日志、可访问性树、截图和阶段报告。
强制清理不能视为正常退出。清理仅限本次子进程组及已记录且仍确认归属的目标进程；
证据留待临时 runner 销毁和制品审查。

禁止在工作站或 self-hosted runner 运行。工作流令牌只有 contents 读取权限，仅用于获取
发布资产，不传给应用。环境门禁用于防止误运行，不是对蓄意伪造 hosted 环境的安全证明。
